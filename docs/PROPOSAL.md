# 떠날이유_기획서_최종_v3

## AI 기반 소도시 관광 큐레이션 서비스

### “광역시 말고, 지금 바로 갈 수 있는 소도시 여행”

---

# 1. 프로젝트 개요

## 프로젝트명 (가제)

### 떠날이유

> 광역시를 벗어나 소도시 숨은 여행지를 발굴하는 AI 기반 실시간 관광 큐레이션 서비스
> 

---

## 프로젝트 소개

여행을 좋아한다고 말하지만, 막상 가는 곳은 항상 똑같습니다.

- 제주도, 부산, 서울만 반복
- 새로운 국내 여행지를 모름
- 소도시 여행의 매력을 아직 발견하지 못함
- 한 곳만 가기엔 아쉽고, 코스 짜기는 귀찮음

본 서비스는 **광역시를 제외한 소도시(OO시, XX군) 중심**으로:

짧은 시간에, 부담 없는 비용으로, 메인 관광지 + 주변 코스를 묶어서 —

생성형 AI와 TourAPI를 활용해 **“지금 바로 떠날 수 있는 소도시 하루 코스”** 를 제안하는 서비스입니다.

---

# 2. 문제 정의

## 반복되는 여행 패턴

### 현황

대부분의 20~30대는 **제주·부산·서울**만 반복적으로 방문합니다.

- 국내 여행지 다양성 부족
- 광역시 중심의 여행 패턴 고착화
- 소도시 관광 콘텐츠 노출 부족
- 새로운 여행지 발굴 의지는 있으나 정보 부족

---

## 소도시 여행의 장벽

### ① 인지도 부족

“군산? 거기 뭐 있어?” - 소도시에 뭐가 있는지 모름

### ② 코스 구성의 어려움

“한 곳만 가기엔 아쉬운데, 주변에 뭐가 있지?” - 주변 관광지 연계 정보 부족

### ③ 계획 피로도

검색하고, 비교하고, 동선 짜는 과정 자체가 부담

### ④ 동기 부재

정보는 넘치는데 “왜 거기를 가야 하는가”는 아무도 말해주지 않음

---

## 기존 관광 서비스의 한계

현재 관광 서비스들은:

- **광역시 중심** 추천 (서울, 부산, 제주 등)
- **단일 관광지** 나열 (주변 코스 연계 부족)
- **정적 추천** (시간대, 날씨 무관)
- **일정별 차별화 없음** (당일/1박 구분 없이 동일 정보)

**본 서비스는 이 모든 것을 해결합니다.**

# 3. 기획 의도

## 소도시 관광 활성화 + 사용자 만족도 향상

본 서비스는 세 가지를 동시에 해결합니다.

### 1. 지역 차별화: 광역시 말고 소도시

**제주·부산 말고, 군산·통영·강릉**
- 광역시를 제외한 OO시, XX군 중심 추천
- 숨겨진 국내 관광지 발굴
- 지역 관광 활성화 기여

### 2. 코스 구조: 메인 + 부가 묶음 제안

**한 곳만 가면 아쉬운 소도시 여행 특성 반영**
- 메인 관광지 1곳 + 주변 연계 관광지 자동 추천
- 일정별(당일/1박/2박) 코스 확장
- 효율적인 동선 최적화

### 3. 실시간성: 지금 이 순간 기준 추천

**“언젠가”가 아닌 “지금 바로”**
- 현재 시간, 날씨, 일몰 시간 반영
- 최적의 방문 타이밍 제안
- 출발 시간 가이드

---

**결과적으로 사용자가 서비스를 닫을 때**

“나중에 가야지”가 아니라

**“이번 주말에 군산 가야겠다”** 고 생각하게 만드는 것이 목표입니다.

## 5-1. 소도시 중심 추천 ⭐ (핵심 차별화 1)

**광역시 제외, OO시·XX군 집중**

### 대상 지역

```
광역시 제외:
서울, 부산, 대구, 인천, 광주, 대전, 울산, 세종

소도시 중심:
군산시, 경주시, 강릉시, 전주시, 통영시,
안동시, 공주시, 부여군, 담양군, 여수시,
속초시, 태백시, 삼척시, 정선군 등
```

### 추천 예시

```
일반 서비스: "부산 해운대 추천"
본 서비스: "통영 동피랑 벽화마을 추천"

일반 서비스: "제주 성산일출봉"
본 서비스: "태백 태백산 눈꽃축제"

일반 서비스: "서울 경복궁"
본 서비스: "공주 공산성 + 무령왕릉"
```

**차별점:**
- 오버투어리즘 완화
- 지역 관광 활성화
- 숨겨진 명소 발굴
- 한국관광공사 정책 방향과 일치

---

## 5-2. 메인 + 부가 코스 구조 ⭐ (핵심 차별화 2)

**소도시는 한 곳만 가면 아쉬움 → 주변 코스 자동 연계**

### 코스 구조

```
1단계: 메인 관광지 선정
사용자 취향 기반 핵심 1곳 추천

2단계: 일정 확인
당일치기 / 1박2일 / 2박3일

3단계: 부가 관광지 추가
일정에 맞게 주변 관광지를 동선 기준으로 추가

4단계: 최적 동선 제안
Kakao Map으로 효율적인 이동 경로
```

### 실제 예시: 군산 당일치기

```
메인: 군산 근대역사박물관 (2시간)
  ↓ 도보 5분
부가1: 경암동 철길마을 (30분)
  ↓ 도보 10분
부가2: 이성당 빵집 (30분)
  ↓ 차량 15분
부가3: 군산 내항 야경 (30분, 석양 타이밍)

총 소요: 약 4시간
예상 비용: 입장료 무료 + 교통비 약 2만원
```

### 실제 예시: 공주·부여 1박2일

```
Day 1
메인: 공주 공산성 (2시간)
부가1: 무령왕릉 (1시간)
부가2: 공주 한옥마을 (1시간)

Day 2
메인: 부여 정림사지 (1시간)
부가1: 궁남지 (1시간)
부가2: 백제문화단지 (2시간)

총 소요: 1박2일
예상 비용: 숙박 5만원 + 입장료 1만원 + 교통비 3만원
```

**차별점:**
- 단일 관광지 X → 완성된 코스 O
- 일정별 자동 확장 (당일/1박/2박)
- 동선 최적화
- 시간 + 비용 계산까지 제공

## 5-3. 실시간 타이밍 추천 ⭐ (핵심 차별화 3)

**정적 추천이 아닌, 현재 시간·날씨·일몰 기준 추천**

### 실시간 컨텍스트 활용

```tsx
const realTimeContext = {
  currentTime: "16:30",
  sunsetTime: "18:45",  // 2시간 15분 남음
  weather: "맑음",
  temperature: "18도",
  dayOfWeek: "토요일",
  season: "가을"
}
```

### AI 프롬프트 예시

```
지금 시각은 16:30이고, 석양까지 2시간 15분 남았습니다.
날씨는 맑고 기온은 18도입니다.
토요일이라 사람이 많을 수 있습니다.

이 조건에서 군산 내항을 추천한다면?
```

### AI 응답 예시

```
"지금 출발하면 박물관과 철길마을을 보고
석양 시간에 딱 군산 내항에 도착할 수 있어요.
주말이지만 저녁 시간대라 오히려 한적합니다."
```

**차별점:**
- “언젠가” → “지금 바로”
- 최적 방문 타이밍 제안
- 실시간 날씨 반영
- 비성수기/비인기 시간대 추천 가능

## 5-4. 부정 필터 기반 추천

**“무엇을 좋아하세요?”가 아닌 “무엇을 피하고 싶으세요?”**

사람들은 자신이 좋아하는 것보다 **싫어하는 것을 더 명확히 압니다.**

### 부정 필터 예시

```
✅ 사람 많은 곳 싫어요
✅ 입장료 비싼 곳 피하고 싶어요
✅ SNS 찍어야 하는 분위기 부담스러워요
✅ 시끄러운 곳 싫어요

→ AI가 이 조건을 "제외"하고 추천
```

**차별점:**
- 심리적으로 더 솔직한 응답 유도
- 미스매칭 확률 감소
- 사용자가 진짜 원하는 여행 발굴

---

## 5-5. AI 감성 스토리텔링

TourAPI 딱딱한 설명을 감성 콘텐츠로 재구성

### 예시

**기존 (TourAPI 원문):**

> “군산 근대역사박물관은 군산의 근대문화 및 해양문화를 주제로 합니다.”
> 

**본 서비스 (AI 감성 재구성 + 실시간 컨텍스트):**

> “일제강점기 수탈의 아픔이 서린 곳이지만, 지금은 근대건축의 매력을 느낄 수 있는 공간입니다.
지금(16:30) 출발하면 박물관을 천천히 둘러보고 경암동 철길마을을 걸으며
석양 무렵 군산 내항에 도착해 빛나는 바다를 볼 수 있어요.
토요일 저녁이라 오히려 한적하고, 오늘처럼 맑은 날엔 야경이 특히 아름답습니다.”
>

## 5-6. 여행 부담 최소화 정보

사용자가 여행을 시작하지 못하는 **현실적 장벽**을 낮추기 위해:

- 당일치기 가능 여부
- **예상 총 비용** (교통비 + 입장료 + 식비)

- 혼자 여행 적합도
- 짧은 코스 추천 (3~4시간 완주)
- **지금 출발 시 도착 시간**
- **마지막 대중교통 시간**
- **일정별 확장 옵션** (당일 → 1박 → 2박)

## AI 역할 (프롬프트 설계 중심)

### 1. 취향 기반 메인 관광지 선정

```
프롬프트 예시:

사용자 취향:
- 관심사: 근대건축, 드라마 촬영지
- 스타일: 혼자, 조용한 곳 선호
- 회피: 사람 많은 곳, 비싼 입장료

조건:
- 지역: 광역시 제외, 전북/충남 소도시
- 일정: 당일치기

TourAPI 데이터를 기반으로 최적의 메인 관광지 1곳을 추천하세요.
```

### 2. 실시간 컨텍스트 반영 추천 이유 생성

```
프롬프트 예시:

관광지: 군산 근대역사박물관
현재 시각: 16:30
석양까지: 2시간 15분
날씨: 맑음
요일: 토요일

이 조건에서 해당 관광지를 추천한다면 어떻게 표현하시겠습니까?
감성적이면서도 구체적인 추천 이유를 작성하세요.
```

### 3. 일정별 부가 관광지 연계 코스 생성

```
프롬프트 예시:

메인 관광지: 군산 근대역사박물관
주변 관광지: [TourAPI locationBasedList2 결과]
사용자 일정: 당일치기 (4시간)

효율적인 동선 순서로 메인 + 부가 3곳을 묶어
4시간 코스를 생성하세요. 이동 시간과 방법을 포함하세요.
```

### 4. 부정 필터 기반 필터링

```
프롬프트 예시:

사용자 회피 조건:
- 사람 많은 곳
- 입장료 1만원 이상
- SNS 분위기 강한 곳

TourAPI 결과 중 위 조건에 해당하는 관광지를 제외하세요.
```

## 프롬프트 체계 구조

```
1단계: 사용자 입력 수집
   ↓
2단계: TourAPI 데이터 조회
   ↓
3단계: 실시간 컨텍스트 수집
   ↓
4단계: AI 프롬프트 생성
   - 메인 관광지 선정
   - 부가 관광지 연계
   - 감성 스토리 생성
   - 실시간 추천 이유 생성
   ↓
5단계: 결과 제공
```

## 16-4. 프롬프트 엔지니어링 구조

### LaaS 활용 프롬프트 설계

**1. 메인 관광지 선정 프롬프트**

```
입력:
- 사용자 취향: {preferences}
- 회피 조건: {avoidances}
- 지역: 광역시 제외, {selected_region}
- 일정: {duration}
- TourAPI 검색 결과: {tourapi_results}

출력:
메인 관광지 1곳을 선정하고 선정 이유를 설명하세요.
```

**2. 부가 관광지 연계 프롬프트**

```
입력:
- 메인 관광지: {main_place}
- 주변 관광지 목록: {nearby_places_from_locationBasedList2}
- 사용자 일정: {duration} (당일/1박/2박)

출력:
일정에 맞는 부가 관광지를 선정하고 동선 순서를 제안하세요.
이동 시간과 방법을 포함하세요.
```

**3. 실시간 컨텍스트 반영 추천 이유 생성**

```
입력:
- 관광지: {place_name}
- 현재 시각: {current_time}
- 석양까지: {time_until_sunset}
- 날씨: {weather}
- 요일: {day_of_week}

출력:
이 조건에서 해당 관광지를 추천하는 감성적이고 구체적인 이유를 작성하세요.
```
